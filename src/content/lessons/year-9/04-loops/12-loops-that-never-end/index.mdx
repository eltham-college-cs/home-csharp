## The big idea

An **infinite loop** is a loop whose condition never becomes false. The four usual causes:

1. **No update.** The variable never changes.
2. **Wrong direction.** It changes, but away from the exit (`+ 1` instead of `- 1`).
3. **The condition can't be false**, like `while (5 > 3)`.
4. **The sneaky one.** You update a *different* variable from the one in the condition.

C# adds one more: the update is written, but it is **not inside the curly braces**, so it never repeats. More on that below.

<Note title="Rescue kit">
In Visual Studio press the red stop button. In a terminal press Ctrl + C. On this site, the program is stopped for you after 3 seconds and you'll see "Your program didn't finish".
Then check: does the body change the variable in the condition? In the right direction? Is the update inside the `{ }` of the loop? Can the condition ever be false?
</Note>

## Two C# traps

In C#, **only the curly braces** decide which lines are inside the loop. The spaces at the start of a line make code easier to read, but C# ignores them.

Without braces, a `while` repeats just **one** line: the next one. The update below *looks* as if it is inside the loop, but it isn't.

<CsChecker task="no-braces" />

A **semicolon** straight after `while (…)` is even sneakier. The `;` is an empty instruction, and that empty instruction is the whole loop. The lines in the `{ }` never get a turn, so nothing is printed and the program never finishes.
